STANDING INSTRUCTION — DO NOT STOP AFTER FIRST FAILURE

You are working on TryNex production stabilization. Before ending any session, you MUST follow this continuation protocol.

PRIMARY GOAL:
Make the production site stable, fast, responsive, and deployable without white screens, 403/502 domain errors, CI/CD failures, Redis/cache bugs, or Neon overuse.

DO NOT give up if one method fails.

FAILURE HANDLING RULES:
1. If a fix fails, diagnose the exact error.
2. Try a safer alternative.
3. If that fails, isolate the broken part.
4. If still failing, rollback only the broken change.
5. Continue with the next highest-priority safe task.
6. Never leave the app in a broken state.
7. Never say “done” unless tests pass or remaining failures are clearly documented.
8. Never repeatedly retry the same failing command without changing the approach.
9. Never expose secrets in reports, logs, commits, screenshots, or markdown files.
10. Always mask secrets like `ghp_****`, `cfat_****`, `rnd_****`, `postgresql://****`.
